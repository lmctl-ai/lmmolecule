# Schema v0 (`schema/lmmolecule.dsl.json`)

Generated by `scripts/gen-schema.py` from the `method(r, "Type", "name", {params}, "ret", ...)`
registrations in `cpp/main.cpp` (so schema and host cannot drift); `test.sh` also diffs the
registry against `lmscript --dsl-signatures`. One context, `md: Md`; types `Md` (7 methods),
`System` (29 methods), `Sim` (29 methods); no free functions. 65 methods total (0.1.2 added
`Md.threads`, `System.load_pdb/water/water_box/constrain/dielectric/andersen`,
`Sim.save_pdb/dof/mark/msd/rdf/rdf_pair`).

## Rigid water, constraints, thermostats (0.1.2)

- `System.constrain(i, j, d)` is `OpenMM::System::addConstraint`; the Reference and CPU platforms
  apply SETTLE to three-site clusters and CCMA/SHAKE otherwise. A constraint on a zero-mass particle
  is rejected at `sim`. `build_sim` calls `applyConstraints`/`applyVelocityConstraints` once so an
  approximate start lands on the constraint manifold; `LocalEnergyMinimizer` and
  `setVelocitiesToTemperature` respect constraints by themselves.
- `Sim.temperature` divides by `Sim.dof() = 3 * mobile - constraints` (no centre-of-mass removal is
  added). A rigid water keeps 6 of 9 degrees of freedom.
- `System.water(model, x, y, z)` places one rigid molecule (oxygen at the point, bisector along +x,
  plane xy); `water_box(model, n, spacing, seed)` places `n^3` molecules on a cubic grid with random
  orientations (uniform unit quaternions from `std::mt19937_64(seed)`) in a box `n * spacing`;
  0.31 nm spacing is liquid density. Both add O charge/LJ, H charges (explicit `lj_particle` with
  epsilon 0 so a later `sys.lj(...)` default does not reach them), the three intramolecular
  exclusions and the three constraints. Models: TIP3P (r 0.09572 nm, 104.52 deg, q_O -0.834,
  sigma 0.315061, eps 0.636386) and SPC/E (0.1 nm, 109.47 deg, -0.8476, 0.316557, 0.650194).
  Masses 15.99943 / 1.007947. The script still chooses `coulomb("pme", rc)` with `2 rc < box`.
- `System.andersen(T, rate, seed)` adds `OpenMM::AndersenThermostat` (use with `verlet`).
- `System.barostat` now requires `T > 0` (the Monte Carlo acceptance is `exp(-dW / kT)`) and
  `check_finite` also rejects a box whose vectors or volume stopped being positive and finite.
- `System.gas` tests each candidate against every particle already in the system (earlier `gas`,
  lattice or water calls too) and errors after 200 rejected trials instead of placing an overlap.
- `coulomb("cutoff")` keeps its name and gains the alias `"reaction_field"`; `System.dielectric(eps)`
  sets the reaction-field dielectric (default 78.3; 1.0 gives `k q q (1/r - 1/rc)`, a plain shifted
  cutoff). Closed-form oracle in `tests/water_constraints.lms`.
- `Md.threads(n)` sets the CPU platform `Threads` property for every later `Sim` (1 keeps reruns
  byte-identical; `DeterministicForces` stays on).

## Files and analysis helpers

- `System.load_pdb(path)` reads `ATOM`/`HETATM` of the first model (x, y, z in Angstrom columns
  31-54 -> nm), element from columns 77-78 or derived from the atom name, mass from a 42-element table
  (unknown element = error), and `CRYST1` as the box. Interactions are added by the script.
  `Sim.save_pdb(path)` writes `CRYST1`, `HETATM` records (resname `MOL`) and `END` at 0.001 A.
- `Sim.mark()` stores the current positions; `Sim.msd()` returns the mean squared displacement of
  the mobile particles since then. OpenMM never wraps positions, so periodic systems give the
  Einstein relation `D = MSD / (6 t)` directly.
- `Sim.rdf(path, rmax, bins, frames, stride)` averages the pair histogram over `frames` snapshots
  `stride` steps apart (reporters fire as in `Sim.step`), minimum image, `rmax < box / 2`, at most
  20000 particles, and writes `r g` CSV normalised by `N rho shell / 2` per frame.
  `Sim.rdf_pair(path, sym_a, sym_b, ...)` restricts the pairs to two element symbols (`*` = any);
  the ideal count is `N_a N_b shell / V` (halved when both symbols coincide), so the water O-O
  g(r) and the rock-salt Na-Cl coordination (6) come out directly.

## Unit conventions (OpenMM standard MD units)

| Quantity | Unit | Notes |
| --- | --- | --- |
| Length / position / cutoff | `nm` | $1\text{ nm} = 10\,\text{\AA}$ |
| Time / timestep $\Delta t$ | `ps` | $1\text{ ps} = 1000\text{ fs}$ |
| Mass | `amu` (`g/mol`) | coherent: $1\text{ amu}\cdot(\text{nm}/\text{ps})^2 = 1\text{ kJ/mol}$ |
| Velocity | `nm/ps` | $1\text{ nm/ps} = 1000\text{ m/s}$ |
| Energy (`ke`, `pe`, `energy`, $\varepsilon$) | `kJ/mol` | $k_B = R = 0.008314462618\text{ kJ/(mol}\cdot\text{K)}$ |
| Force (`fx`, `fy`, `fz`) | `kJ/(mol·nm)` | $-\nabla_i U$ |
| Charge | `e` | $1/(4\pi\varepsilon_0) = 138.935457644382\text{ kJ}\cdot\text{nm}/(\text{mol}\cdot e^2)$ |
| Angle / phase | `rad` | $\pi \approx 3.141592653589793$ |
| Temperature / pressure | `K` / `bar` | `barostat(pressure_bar, temp_K, freq, seed)` |

## Determinism across platforms and reruns

- `md.platform("reference" | "cpu")` selects OpenMM's double-precision `"Reference"` platform or
  mixed-precision SIMD `"CPU"` platform (default `"Reference"`; the setting applies to every `Sim`
  created after the call). On `"CPU"`, `Threads=1` and
  `DeterministicForces=true` are passed to `OpenMM::Context` so force accumulation order is
  deterministic.
- Before creating an `OpenMM::Context`, `build_sim` resets `SimTKOpenMMUtilities`'s static SFMT
  generator and clears its cached Box-Muller spare normal (`nextGaussianIsValid`) so repeated
  `Sim` creations with the same seed in one process produce identical trajectories.
- `Sim.report(path, every)` writes `# step time ke pe energy temperature` followed by
  space-separated rows (`%.10g`) at step 0 and every `every` steps. `Sim.xyz(path, every)` writes
  multi-frame XYZ in `nm`.

## Validation and failure behaviour

- Lepton expressions (`md.eval`, `custom_external`, `custom_bond`, `custom_nonbonded`) are parsed and
  walked before anything optimizes them: a constant sub-expression that is not finite (`sqrt(-1)`,
  `1/0`) is an error, because Lepton's `optimize()` compares folded constants with `==` and loops forever
  on a NaN constant. Parameter names `x y z r pi e` are reserved.
- `Sim.step` / `Sim.minimize` check positions and velocities after every integration chunk; `ke`, `pe`,
  `energy`, `temperature`, `fx..fz` and report rows refuse non-finite values. All exit 3 with the step.
- `lj(eps, sigma, cutoff)` and `coulomb(method, cutoff)` share one OpenMM `NonbondedForce`, so a non-zero
  LJ cutoff together with `coulomb("none")` or a different Coulomb cutoff is an error at `System.sim`.
- `coulomb("cutoff", rc)` (and charges with only an LJ cutoff) is OpenMM's reaction-field Coulomb with
  dielectric 78.3, not a plain truncation.
- `OpenMMException`s (for example two custom forces giving one global parameter different values) are
  reported as run errors (exit 3) with OpenMM's message.
